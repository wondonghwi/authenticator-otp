# 키체인 등록과 이름 정하기

이 도구는 **본인이 소유하고 등록 권한이 있는 TOTP 비밀키**를 사용합니다. 서비스가 외부 인증 앱용 설정 키나 URI를 제공해야 합니다. 다른 사람의 키를 가져오거나 기존 키체인의 비밀값을 추출하는 절차는 제공하지 않습니다.

## 먼저 구분할 값

- **비밀키(secret)**: 인증 코드를 생성하는 장기 비밀값입니다. 서비스의 2단계 인증 등록 화면에서 받는 Base32 문자열이나 `otpauth://totp/...` URI입니다.
- **OTP**: 비밀키와 현재 시간으로 만든 6자리 또는 8자리 코드입니다. 키체인의 암호란에 OTP를 저장하면 안 됩니다.
- **복구 코드**: 인증 수단을 잃었을 때 쓰는 별도 값입니다. 이 도구의 입력이 아닙니다. 서비스 안내에 따라 별도로 안전하게 보관합니다.

QR 코드에는 비밀키가 들어갈 수 있습니다. QR·설정 키·전체 URI를 온라인 디코더, 메신저, 이슈, 스크린샷에 올리지 마세요. 서비스가 직접 제공하는 텍스트 설정 키를 우선 사용합니다.

## 키체인에 새 암호 항목 등록하기

1. 서비스의 보안 설정에서 인증 앱(TOTP) 등록 화면을 열고, 직접 제공하는 설정 키 또는 전체 TOTP URI를 확인합니다. 등록을 완료하기 전에는 원래 인증 수단과 복구 방법을 유지합니다.
2. Spotlight에서 **키체인 접근(Keychain Access)** 을 실행합니다. macOS의 **암호(Passwords)** 앱과는 다른 앱입니다.
3. 왼쪽에서 **login(로그인)** 키체인을 선택하고 **암호(Passwords)** 분류를 선택합니다. 로컬 보관을 위해 iCloud 키체인이나 시스템 키체인을 선택하지 않습니다.
4. 메뉴의 **파일 → 새로운 암호 항목(File → New Password Item)** 을 선택합니다. macOS 버전에 따라 메뉴 위치나 번역이 다를 수 있습니다.
5. **키체인 항목 이름**에 `auth-otp`, **계정 이름**에 `default`, **암호**에 자신의 Base32 설정 키 또는 전체 TOTP URI를 입력합니다. 암호 입력을 표시하는 옵션은 끕니다.
6. **추가(Add)** 를 눌러 저장합니다. 서비스에서 복사한 비밀키가 클립보드에 남아 있다면 다른 민감하지 않은 내용을 복사하고, 사용 중인 클립보드 기록에서도 제거합니다.
7. 저장소 폴더에서 `./bin/auth-otp --check`를 실행하여 읽기·형식을 검증합니다. 읽기 권한 창이 나오면 아래 안내를 확인합니다.
8. `./bin/auth-otp`를 실행한 뒤 서비스의 인증 입력란에 붙여 넣어 등록을 마칩니다. 실제 코드가 서비스에서 받아들여지는지 확인하고 복구 수단을 보관합니다.

비밀키를 명령어 인자로 넣는 `security add-generic-password ... -w 실제비밀키` 방식은 사용하지 마세요. 셸 기록과 프로세스 인자에 남을 수 있으므로 이 가이드는 키체인 접근의 암호 입력란을 사용합니다. `.env`, JSON 설정, 셸 환경변수에도 비밀키를 저장하지 않습니다.

## 이름을 정하는 규칙

앱 이름은 Spotlight 검색용 표시 이름입니다. 키체인 이름(`--service`)과 계정(`--account`)은 비밀키를 찾는 정확한 두 값입니다. 두 값이 함께 일치해야 합니다.

| 사용 목적 | 키체인 이름 | 계정 별칭 | 앱 이름 |
| --- | --- | --- | --- |
| 기본 한 계정 | `auth-otp` | `default` | `auth-otp` |
| 주 계정 | `auth-otp.personal` | `primary` | `Personal OTP` |
| 보조 계정 | `auth-otp.secondary` | `primary` | `Secondary OTP` |

이름·계정은 영문이나 숫자로 시작하는 1~128자의 영문·숫자·`.`·`_`·`-`·`@`를 사용합니다. 실명·사번·실제 메일 주소는 필요하지 않습니다. `personal`, `primary` 같은 별칭을 쓰면 앱 설정에 개인 식별자를 남기지 않을 수 있습니다.

개인 프로필 예시는 다음과 같습니다. 먼저 키체인에 해당 이름·계정으로 항목을 등록합니다.

```sh
./bin/auth-otp --service auth-otp.personal --account primary --check
./bin/auth-otp --service auth-otp.personal --account primary
./scripts/install-app.sh --name "Personal OTP" --service auth-otp.personal --account primary
```

`--name`만 바꾸면 검색 이름만 달라집니다. 키체인 이름이나 계정을 변경했다면 실행·설치 옵션도 함께 바꿔야 합니다. 같은 이름·계정으로 중복 항목을 만들지 말고 기존 항목을 수정하거나 다른 조합을 선택합니다.

## Base32와 전체 URI 중 무엇을 저장할까?

서비스가 기본 SHA1 / 6자리 / 30초 TOTP를 사용하면 Base32 설정 키만 저장할 수 있습니다. 다른 설정을 사용한다면 서비스가 제공한 전체 `otpauth://totp/` URI를 저장하는 편이 정확합니다.

형식만 보여 주는 예시는 아래와 같습니다. `YOUR_BASE32_SECRET`은 실행 가능한 예제 키가 아닌 자리 표시자입니다.

```text
otpauth://totp/Example:primary?secret=YOUR_BASE32_SECRET&issuer=Example&algorithm=SHA256&digits=8&period=30
```

알고리즘·자리수·주기를 임의로 바꾸면 서비스가 코드를 거절합니다. URI의 이름·issuer는 코드 계산에는 사용하지 않지만 개인 식별 정보를 포함할 수 있으므로 URI 전체를 비밀값으로 다룹니다. HOTP URI는 지원하지 않습니다.

## 키체인 접근 권한

macOS가 암호를 읽으려는 도구에 대한 접근 허용을 물을 수 있습니다. 이 구현은 Apple의 `/usr/bin/security`를 호출하므로 권한 창에 앱 이름 대신 `security`가 보일 수 있습니다. **본인이 앱이나 CLI를 실행한 직후인지 확인하고 일회성 허용부터 사용합니다.**

키체인 항목의 **접근 제어(Access Control)** 에서 모든 응용 프로그램에 접근을 허용하지 마세요. `security`에 항상 허용하면 이 앱 외의 프로그램도 같은 시스템 도구를 호출할 수 있습니다. 편의성과 접근 범위를 이해한 뒤 선택해야 하며, 이 도구가 매번 Touch ID나 Mac 암호 확인을 강제하는 것은 아닙니다.

키체인이 잠겨 있거나 접근을 거부하면 실패합니다. 권한 우회, 자동 잠금 해제, 모든 앱 허용은 구현하지 않습니다. [Apple의 키체인 접근 권한 안내](https://support.apple.com/en-gb/guide/mac-help/kychn002/mac)를 참고하세요.

## 수정·삭제·복구

비밀키를 바꾸려면 키체인 접근에서 자신이 만든 항목을 열고 암호를 수정합니다. 이때 서비스에 등록된 비밀키와 일치해야 합니다. 서비스의 2단계 인증을 재등록했다면 새 비밀키로 갱신합니다.

삭제하려면 정확한 이름·계정의 항목만 삭제합니다. 키체인 전체 초기화나 `login.keychain-db` 파일 삭제는 하지 않습니다. 이 도구는 비밀키를 백업·내보내기·동기화하지 않습니다. 키체인을 잃었을 때를 대비해 서비스의 복구 수단을 따로 유지합니다.

회사나 조직이 관리하는 계정에 사용하려면 해당 조직의 인증정보 보관 정책을 먼저 따릅니다.
